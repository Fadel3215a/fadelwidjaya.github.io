Automated Infrastructure Reporting

A Python-based automation pipeline developed to streamline daily reporting on the LRT Jakarta Phase 1B infrastructure project.

Origin

This project came from my work as Site Coordinator & Resources Specialist on Len Railway System — LRT Jakarta Phase 1B, Velodrome to Manggarai. Part of my role involved preparing operational reports, monitoring project timelines and submission status, and maintaining structured project information in Excel and Google Sheets.

As reporting became a recurring daily task, I saw an opportunity to make the process more efficient — not by changing what information management needed, but by reducing the repetitive manual work involved in compiling it.

Problem

Daily infrastructure reporting involved repetitive manual compilation. Project data — timelines, submission status, operational progress — lived in structured spreadsheets, but pulling it together into consistent reports required the same steps each day.

That repetition created operational overhead and made consistency harder to maintain. Small variations in how data was compiled could produce reports that did not align, which mattered because these reports supported management decision-making and progress tracking.

Approach

I started by mapping the existing reporting workflow: what data sources were used, what the output needed to look like, and where manual steps introduced delay or inconsistency. Rather than proposing a new tracking system, I focused on automating the compilation step within the workflow already in use.

I explored how Python could connect to the structured data I was already maintaining and generate reports in a repeatable format. The goal was to preserve the operational requirements while removing repetitive manual assembly.

Implementation

I developed a Python-based automation pipeline — a custom tool that consolidates project data from structured spreadsheet sources and generates operational reports. The pipeline was built around the actual reporting workflow on the project, not around abstract automation concepts.

The tool integrates with the Excel and Google Sheets data I was already responsible for maintaining, processing structured project information and producing report output as part of a repeatable daily workflow.

Outcome

The deliverable was an automated reporting workflow designed to streamline the daily reporting process and improve data consistency. The pipeline replaced manual compilation with a structured, repeatable process tied to the project's existing data sources.

This was a practical operational tool built for a specific project context — not a commercial product. Its value was in making a recurring coordination task more reliable and less dependent on manual repetition.

What I learned

  • Translating operational problems into technical solutions. The starting point was a real reporting workflow I managed daily — not a technology choice looking for a problem.
  • Python automation in practice. Building a pipeline that works with existing spreadsheet data requires understanding both the code and the operational context it serves.
  • Real-world operational requirements. Automation only helps if it respects how stakeholders actually use reports and what information they need to make decisions.
  • Data consistency. Structured, repeatable compilation reduces variation that can undermine trust in operational reporting.
  • Building tools around workflows. The most useful automation follows the work as it already happens, rather than forcing a new process for the sake of using technology.
