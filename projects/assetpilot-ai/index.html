AssetPilot AI

A portfolio prototype exploring how AI-assisted workflows can support digital asset curation — organizing, evaluating, and preparing assets for production while keeping final decisions with a human curator.

Live demo

Overview

AssetPilot AI is a functional portfolio prototype — not a production AI system or commercial DAM product. It demonstrates how AI-assisted workflows can help organize, evaluate, and prepare digital assets for production while keeping final decisions with human curators.

The project applies my operational and coordination thinking to digital asset management: structured information gathering, quality control, decision support, and feedback loops — with AI providing suggestions, not authority.

Problem

AI-generated content and high-volume production pipelines can create large numbers of images, video, audio, 3D assets, and other digital files. These assets need organization, metadata, quality review, version control, comparison, and production-readiness checks before they can be used reliably.

AI can help surface patterns and suggestions, but approval, rejection, and production readiness still require accountable human judgment. The operational challenge is designing a workflow that uses AI assistance without treating AI output as a final decision.

Approach

I built AssetPilot around a human-in-the-loop model. Simulated AI analysis provides suggestions and observations based on asset metadata. The curator reviews each suggestion and can accept, edit, or dismiss it. The curator remains responsible for every final decision — approve, request changes, reject, or mark production-ready.

AI recommendations are labeled throughout the application as simulated analysis, AI suggestions, or demo confidence — never presented as real machine learning inference.

Workflow

  1. Step Ingestion
  2. Step Metadata
  3. Step Simulated AI analysis
  4. Step Human review
  5. Step Comparison
  6. Step Decision
  7. Step Production ready

The broader workflow also includes organization, quality evaluation, version management, and continuous improvement — from asset ingestion through metadata extraction, AI-assisted analysis, human review, and production readiness.

AI architecture

The current implementation uses an AI provider boundary — not direct coupling between UI components and analysis logic:

Asset data → AIAnalysisProvider → AIAnalysisResult → UI

The AIAnalysisProvider interface defines the boundary. The current MockAIAnalysisProvider is a deterministic implementation that generates simulated AI analysis from asset metadata and mock data — not trained models, computer vision, or real inference.

UI components consume structured analysis results, not the mock generator directly. The architecture is designed so a real AI provider could replace the simulated provider later without rewriting the interface layer.

Human-in-the-loop design

AI recommendations are separated from curator decisions by design. Suggestions require explicit accept, edit, or dismiss actions. Approve, request changes, and reject are curator-only actions. Nothing is auto-approved or auto-rejected by AI.

The guiding principle is straightforward: AI suggests. You decide. Review history records curator responses — it is not model training or automated retraining.

Limitations

  • Session-only data — uploads and edits are lost on refresh
  • No database, authentication, or cloud asset storage
  • No real AI inference — simulated/deterministic analysis only
  • Seeded demo assets for portfolio demonstration
  • Duplicate detection is metadata-based, not visual similarity
  • Related asset discovery is metadata-based, not AI-powered visual search
  • Not a production enterprise DAM system or commercial product

What I learned

  • Structured information gathering. Asset curation starts with organized metadata and clear workflow stages — similar to how I approach document control and operational reporting.
  • Quality control as a process. Checklists, review history, and production-readiness gates mirror the dependency-tracking I applied in infrastructure coordination work.
  • Decision support vs. decision authority. Separating AI suggestions from curator decisions required explicit UI labeling and workflow design — not just a disclaimer.
  • Feedback loops. Review history and continuous improvement stages reflect the same pattern I use in operational work: implement, observe, adjust.
  • Product thinking within constraints. Building a functional prototype with session-only state and simulated AI forced clear scope decisions about what the demo could honestly demonstrate.
  • Technical implementation. Provider abstraction, session state management, and metadata-driven discovery taught me how to structure an application around workflow integrity rather than feature accumulation.
