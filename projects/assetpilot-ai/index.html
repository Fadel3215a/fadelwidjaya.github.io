AssetPilot AI v1.5.1 Live

A production-grade, live AI-assisted digital asset management platform. AssetPilot AI combines human-in-the-loop curation, hybrid semantic vector search over 1536-dimensional embeddings, and real-time job execution telemetry — built on Next.js 16 (Turbopack), Prisma 7 + pgvector, and NextAuth v5, deployed on Vercel.

Live demo GitHub repository

Overview

AssetPilot AI v1.5.1 is a live, deployed digital asset management platform built to make AI-assisted curation accountable and observable. It is not a demo only in the browser — it runs as a full-stack application with a persistent database, real authentication, semantic search, and real-time background job execution.

Ingestion → Metadata extraction → Hybrid search (keyword + semantic) → AI-assisted curation → Human decision → Live job telemetry

The core value proposition rests on three pillars:

  • Human-in-the-loop curation. AI suggests classifications, observations, and metadata — but every release decision requires explicit curator action. No automated pipeline can override human judgment.
  • Semantic vector search. Assets are embedded into 1536-dimensional vectors stored in pgvector. A hybrid search dial blends traditional keyword matching with cosine-similarity retrieval so users find assets by meaning, not just by text.
  • Real-time job execution telemetry. Long-running background jobs (embedding generation, ingestion pipelines) stream progress live to the client over Server-Sent Events (SSE) — giving operators a real-time view of every task as it runs.

Problem

Digital asset libraries and high-volume creative pipelines face distinct operational bottlenecks:

  • Fragmented metadata: Assets frequently enter repositories lacking standardized titles, descriptions, technical specifications, and classification tags.
  • Repetitive manual tagging & review: Categorizing hundreds of media files creates significant administrative overhead for creative teams.
  • Hidden duplicates & version chaos: Identifying identical or near-duplicate files across collections is difficult without structured comparison signals.
  • Inconsistent quality standards: Review criteria vary between reviewers without defined checklists and verifiable quality scoring.
  • Disconnected comparison & release gates: Selecting between competing creative directions often happens ad-hoc, with limited auditability before assets reach production.

While automated intelligence can accelerate tagging and surface observations, final release decisions require accountable human judgment. The core challenge is designing a system that delivers assistive intelligence without treating automated suggestions as final decisions.

Approach

AssetPilot is built on a single operating principle: "AI suggests. You decide."

Moving from prototype to a live v1.5.1 release meant rebuilding around a real, persistent stack while keeping the curation discipline intact. The architecture separates core application logic, data persistence, intelligence, and human oversight:

  1. Full-stack application layer: Next.js 16 App Router (Turbopack) with React Server Components for data-fetching performance and a clean route-based API structure.
  2. Persistent data layer: Prisma 7 ORM backed by PostgreSQL (Neon), with pgvector for semantic embeddings and NextAuth v5 for authenticated multi-user access.
  3. Search & retrieval: A hybrid search dial that fuses keyword matching with cosine-similarity over 1536-dimensional vector embeddings.
  4. Human review & decision-making: Mandatory curator approval, decision history, and feedback logging preserved across the rewrite.
  5. Observability: A floating job activity tray streams real-time progress from background tasks over Server-Sent Events.

Architecture & technical architecture

AssetPilot AI v1.5.1 is a full-stack application built on the Next.js App Router. The rewrite moved from client-only state to a persistent, server-backed architecture with a typed database schema, real authentication, and background job execution.

Next.js App Router (Turbopack) → Route Handlers / Server Components → Prisma 7 ORM → PostgreSQL (Neon, pgvector) & NextAuth v5 → Client (grid / drawer / tray)

  • Next.js 16 (Turbopack) App Router: React Server Components for efficient data fetching, route handlers for API endpoints, and Turbopack for faster builds and development.
  • Prisma 7 database layer with pgvector: Typed ORM mapping models to a PostgreSQL database. pgvector stores 1536-dimensional embedding vectors per asset and supports vector nearest-neighbor (<->) queries for semantic retrieval.
  • NextAuth v5 authentication: Real, persistent user accounts with secure session handling — replacing the single-user prototype with authenticated multi-user access.
  • Vercel production deployment pipeline: Continuous deployment from GitHub, with serverless functions for API routes and edge-ready caching for static content.
  • Serverless connection pooling via Neon PostgreSQL: Neon's serverless Postgres with connection pooling keeps the database reachable from short-lived serverless functions without exhausting connections.
  • Node heap memory configuration (4GB): The runtime is tuned with a 4GB Node.js heap to comfortably handle embedding-heavy and ingestion workloads without memory pressure.

AI integration & semantic search

In v1.5.1, asset intelligence is driven by real semantic embeddings rather than a simulated provider. Each asset is embedded into a 1536-dimensional vector and stored in PostgreSQL via pgvector, enabling retrieval by meaning.

  • Embedding generation: Assets are processed by an embedding pipeline that produces 1536-dimensional vectors capturing semantic content.
  • Vector storage: Embeddings persist in a vector(1536) column indexed for approximate nearest-neighbor search.
  • Hybrid retrieval: A search dial combines traditional keyword/text matching with cosine-similarity vector queries, returning assets ranked by blended relevance.
  • Semantic suggestions: The AI layer surfaces curation suggestions grounded in vector similarity to other reviewed assets, while remaining strictly advisory.

Why human-in-the-loop: Semantic retrieval accelerates discovery and helps curators surface candidates, but every approval, edit, and release decision remains an explicit human action. The AI improves efficiency without removing accountability.

Human-in-the-loop design

AI-generated insights are presented strictly as suggestions requiring curator action — a principle that carried over from prototyping to production:

  • Curators can Accept, Edit, or Dismiss individual AI suggestions and observations.
  • Every curator decision is recorded in a persistent decision history (decision history) for full auditability.
  • Approval, change requests, and rejection are exclusively human-triggered actions requiring curator input.
  • No automated pipeline can bypass the curator or auto-promote an asset to a released state.

Key engineering decisions

  • pgvector over a dedicated vector database: Storing 1536-dimensional embeddings directly in PostgreSQL keeps the stack simple and transactional while supporting semantic retrieval.
  • Hybrid search over vector-only retrieval: Blending keyword and cosine-similarity ranking covers exact-name lookups and fuzzy semantic matches in one interface.
  • Server-Sent Events over WebSockets: SSE provides one-way real-time telemetry to the client with minimal infrastructure, ideal for monitoring background jobs.
  • Neon serverless Postgres with connection pooling: Keeps the database reachable from Vercel serverless functions without connection exhaustion at scale.
  • 4GB Node heap configuration: Sized the runtime to handle embedding generation and large ingestion batches without memory pressure.
  • Strict human governance: Mandatory curator decisions on all state transitions maintain curation accountability in a production, multi-user system.

Outcome

AssetPilot AI v1.5.1 ships as a live, deployed production application available at assetpilot-ai-omega.vercel.app. It demonstrates how a full-stack DAM can combine human accountability with real semantic intelligence and observable, real-time operations.

The platform validates that AI-assisted curation is most effective when the technology accelerates discovery and surfaces relevant candidates while preserving final responsibility with a human curator — now backed by a persistent database, real authentication, and live job telemetry rather than browser-only state.

Challenges & technical considerations

  • Serverless cold starts: Vercel serverless functions can impose cold-start latency on first requests; mitigations focus on efficient static/data caching where possible.
  • Embedding pipeline cost & latency: Generating 1536-dimensional embeddings for large libraries is compute- and time-intensive, making the background job/telemetry system essential.
  • Vector index tuning: Approximate nearest-neighbor (ANN) indexing trades a small amount of recall for query speed — balancing index settings with retrieval quality is an ongoing consideration.
  • Connection management: Relying on Neon connection pooling ensures serverless functions stay within connection limits under concurrent load.
  • Scope: Built as a focused vertical DAM platform; it intentionally does not attempt to be a generic enterprise application server.
