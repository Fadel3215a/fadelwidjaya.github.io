Digital Asset Management · AI-Assisted Curation

AssetPilot AI

An engineering prototype for digital asset management and AI-assisted creative curation. The project explores how creative asset libraries can combine structured metadata extraction, deterministic asset intelligence, curation workflows, side-by-side comparison, and human-in-the-loop review.

Live demo GitHub repository

Overview

AssetPilot AI is a browser-based engineering prototype for organizing, evaluating, and curating digital creative assets. It models a structured operational workflow:

Asset ingestion → Metadata extraction → Quality & health checks → Discovery & duplicate detection → Simulated AI analysis → Human curator review → Comparison → Decision → Production readiness

The project applies operational process discipline to digital asset operations: establishing clear verification gates, structured data capture, quality standards, and feedback loops. Rather than functioning as a commercial enterprise DAM or physical inventory tool, AssetPilot focuses on workflow integrity, human-in-the-loop interaction patterns, and a swappable AI-provider architecture.

Problem

Digital asset libraries and high-volume creative pipelines face distinct operational bottlenecks:

  • Fragmented metadata: Assets frequently enter repositories lacking standardized titles, descriptions, technical specifications, and classification tags.
  • Repetitive manual tagging & review: Categorizing hundreds of media files creates significant administrative overhead for creative teams.
  • Hidden duplicates & version chaos: Identifying identical or near-duplicate files across collections is difficult without structured comparison signals.
  • Inconsistent quality standards: Review criteria vary between reviewers without defined checklists and verifiable quality scoring.
  • Disconnected comparison & release gates: Selecting between competing creative directions often happens ad-hoc, with limited auditability before assets reach production.

While automated intelligence can accelerate tagging and surface observations, final release decisions require accountable human judgment. The core challenge is designing a system that delivers assistive intelligence without treating automated suggestions as final decisions.

Approach

AssetPilot is built on a single operating principle: "AI suggests. You decide."

The architecture deliberately separates core application logic from intelligence providers and human oversight:

  1. Asset management logic: Ingestion, format inspection, version indexing, and state mutations.
  2. Quality & health logic: Multi-factor completeness checklists, dimension checks, and readiness scoring.
  3. Discovery & comparison logic: Multi-attribute duplicate candidate detection and keyword/tag relation scoring.
  4. AI provider abstraction: Clean interface boundary isolating analytical inference from UI presentation.
  5. Human review & decision-making: Mandatory curator approval, quality scoring, and feedback logging.

Assets move from initial drag-and-drop ingestion through client-side property extraction, automated quality scoring, duplicate candidate detection, and assistive analysis before reaching the curator review queue. After curator evaluation or side-by-side comparison, assets satisfying all 5 production criteria are released to the production-ready catalog.

Architecture & system design

AssetPilot AI is implemented as a client-side web application using Next.js App Router, TypeScript, and React Context for centralized in-memory state management:

Asset Data / Metadata → AIAnalysisProvider (Interface) → AIAnalysisResult → UI & Curator Workspace

  • Central state store: AssetsContext coordinates asset collections, version histories, activity streams, comparison records, and AI feedback telemetry.
  • Client-side media pipeline: Uses the browser File API to inspect MIME types, byte sizes, and file headers, dynamically mounting temporary Blob object URLs with managed lifecycle cleanup.
  • Media renderers: Direct rendering for native image formats, HTML5 video, and audio players, with structured placeholder states for 3D model formats.
  • AI provider boundary: The AIAnalysisProvider TypeScript interface decouples all UI components from analysis implementation details.

AI integration & intelligence layer

To ensure technical transparency: the current implementation uses a simulated, deterministic AI provider (MockAIAnalysisProvider). It does not connect to external LLM endpoints, computer vision models, or vector databases.

Analysis outputs are computed deterministically from asset attributes:

  • Tag recommendations: Derived by evaluating asset type mapping tables, collection taxonomy keywords, and AI-origin flags.
  • Quality observations: Evaluated against completeness rules, version thresholds, and previous review statuses.
  • Comparison summaries: Generated by computing score deltas, format differences, and metadata completeness ratios between paired assets.
  • Readiness suggestions: Rule-based verification evaluating whether review decisions and metadata prerequisites align with release criteria.

Architectural value: By defining a formal AIAnalysisProvider contract, the application decouples presentation components from the analysis source. A production implementation can replace MockAIAnalysisProvider with a real multimodal inference provider (such as a vision-language model or embedding service) without refactoring UI views or curation workflows.

Human-in-the-loop design

AI-generated insights are presented strictly as suggestions requiring curator action:

  • Curators can Accept, Edit, or Dismiss individual tag suggestions and observations.
  • Curator responses are tracked as session telemetry (aiStats) to quantify interaction efficiency.
  • Approval, change requests, and rejection are exclusively human-triggered actions requiring curator notes.
  • No automated logic or AI suggestion can bypass the curator or auto-promote an asset to production status.

Key engineering decisions

  • Provider boundary over hardcoded logic: Introducing the AIAnalysisProvider interface ensures the AI layer remains swappable for future real inference endpoints.
  • Deterministic analysis for prototyping: Enabled complete end-to-end UX demonstration, repeatable testing, and zero external latency or API cost.
  • Client-side state & object URLs: Avoided complex server and storage infrastructure for a prototype by managing in-memory state and browser blob URL lifecycles directly.
  • Rule-based multi-factor similarity: Delivered predictable, transparent duplicate and relation scoring using metadata fingerprints without requiring external vector database overhead.
  • Strict human governance: Enforced mandatory human notes and checklist criteria on status transitions to maintain curation accountability.

Outcome

The result is a functional engineering prototype that demonstrates how structured metadata, deterministic asset intelligence, and an AI provider boundary can support a human-led digital asset curation workflow.

AssetPilot successfully validates that AI-assisted tooling is most effective when architected as a decision-support mechanism—accelerating cataloging and surfacing relevant observations while preserving human responsibility for quality and release.

Challenges & technical limitations

  • In-memory session state: Uploaded assets, review decisions, and edits are stored in client memory and reset upon page refresh.
  • No backend database or authentication: Operates as a single-curator client application without user accounts or persistent cloud storage.
  • Simulated AI: Intelligence is deterministic and rule-based; it does not utilize trained machine learning models, computer vision, or external LLM APIs.
  • Metadata-based similarity: Duplicate detection and related asset scoring match structured text and numeric attributes rather than perceptual visual hashes or neural embeddings.
  • Media preview boundaries: Native rendering is supported for images, video, and audio; 3D formats use fallback visual placeholders rather than an interactive WebGL viewport.
  • Scope: Designed as an engineering prototype to evaluate workflow and interaction patterns, not an enterprise commercial DAM.
