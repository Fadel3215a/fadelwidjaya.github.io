AssetPilot AI Live Demo

A human-in-the-loop AI-assisted digital asset curation demo. AssetPilot AI combines a full curation workflow — asset library, review workspace, quality scoring, and production readiness gates — with a simulated, provider-abstracted AI analysis layer that suggests but never decides. Built on Next.js 16 (App Router), React 19, TypeScript, and Tailwind CSS v4, deployed live on Vercel.

Live demo GitHub repository

Overview

AssetPilot AI is an independent, feature-complete portfolio demo exploring how a human curator can organize, evaluate, compare, classify, and prepare digital assets for production — with simulated AI assistance that never replaces human judgment.

To be explicit about the positioning: AssetPilot AI is not a commercial product, not connected to a real organization, and not a production enterprise DAM system. It runs entirely in the browser with session-only state — no database, authentication, or external AI APIs — deployed live at assetpilot-ai-ten.vercel.app.

Discover → Understand → Review → Decide → Prepare for Production

The application models an internal creative-operations workflow: assets arrive, metadata is managed, quality is assessed, AI offers suggestions, and a curator makes every final decision.

How this differs from OpsPilot: AssetPilot AI is a fully-built, deployed portfolio demo with a complete curation workflow, polished UX, and documented design decisions. OpsPilot is an early research prototype exploring AI-assisted operations audit concepts.

Problem

Digital asset teams face growing volume, inconsistent metadata, duplicate files, version sprawl, and pressure to move assets to production quickly. Typical bottlenecks include:

  • Fragmented metadata: Assets enter repositories lacking standardized titles, descriptions, technical specifications, and classification tags.
  • Repetitive manual tagging & review: Categorizing hundreds of media files creates significant administrative overhead.
  • Hidden duplicates & version chaos: Identifying identical or near-duplicate files across collections is difficult without structured comparison signals.
  • Inconsistent quality standards: Review criteria vary between reviewers without defined checklists and verifiable quality scoring.
  • Disconnected release gates: Selecting between competing creative directions often happens ad-hoc, with limited auditability before assets reach production.

AI can help surface patterns and suggestions, but approval, rejection, and production readiness require accountable human judgment. The core design question is how to deliver assistive intelligence without treating automated suggestions as final decisions.

Approach

AssetPilot demonstrates a structured curation workflow built on a single operating principle: "AI suggests. You decide."

  1. Discovery & organization: A library with collections, search, and filters for browsing assets.
  2. Metadata management: Extracted file metadata and editable metadata fields, kept distinct from AI suggestions.
  3. Simulated AI analysis: A deterministic provider suggests tags, collections, and observations for review.
  4. Curator evaluation: Checklist-based quality assessment and curator quality scoring.
  5. Comparison & version history: Side-by-side asset comparison and non-destructive versioning support decision-making.
  6. Production readiness: Checklist-driven gates that only a curator can clear — never an automated decision.

AI architecture & provider abstraction

Asset data → AIAnalysisProvider → AIAnalysisResult → UI

  • AIAnalysisProvider interface: defines the boundary between asset data and AI analysis output.
  • MockAIAnalysisProvider: the current deterministic implementation — portfolio demos stay reproducible without API keys.
  • Consumer contract: UI components consume asset.aiAnalysis, not the mock generator directly.
  • Swap-ready design: a real model could replace the provider behind the same interface without rewriting the UI.

AI outputs are labeled AI Suggestion, Simulated AI Analysis, or Demo Confidence throughout the app — preventing misleading claims about real inference.

Human-in-the-loop design

  • AI suggestions require an explicit Accept, Edit, or Dismiss.
  • Approve, Request Changes, and Reject are curator-only actions.
  • Comparison and production decisions require curator reasoning.
  • Curator feedback history records human responses — it is not model training.
  • Nothing is auto-approved or auto-rejected by AI.

Architecture & technology

AssetPilot AI is a static, client-side application. All state lives in React Context with session-only persistence, and the app is statically exported and served from Vercel.

  • Next.js 16 (App Router): route structure and static pre-rendering for the demo's routes and seeded assets.
  • React 19 + TypeScript: typed domain model (types/), feature components, and UI primitives.
  • Tailwind CSS v4: styling and responsive layout.
  • React Context (session state): library, curation, and AI analysis state with no persistence layer.
  • Vercel deployment: the static out/ build is deployed to Vercel and served at the live demo URL.

Key design decisions

  • Session-only state keeps the demo self-contained and privacy-safe — uploaded files never leave the browser.
  • Deterministic mock AI makes portfolio demos reproducible without API keys or external dependencies.
  • Explicit labeling prevents misleading claims about real inference.
  • Checklist-driven production mirrors real DAM governance patterns.
  • Provider abstraction documents intent for future real AI integration.

Outcome

AssetPilot AI ships as a live, deployed feature-complete portfolio demo available at assetpilot-ai-ten.vercel.app. It demonstrates a complete end-to-end curation workflow, from upload and metadata management through quality evaluation, AI-assisted review, and production-readiness decisions.

The demo validates that AI-assisted curation is most credible when the technology surfaces and accelerates candidate review while preserving every final decision for a human curator.

Limitations

  • Uploads and edits are lost on refresh — session-only state, no persistence.
  • No persistent storage, user accounts, or multi-tenant support.
  • AI is simulated — not connected to OpenAI, Gemini, Anthropic, or similar.
  • Duplicate and related-asset discovery is metadata-based only — not visual or AI similarity.
  • Seeded demo assets are fictional — not real client work.
  • Confidence levels are demo labels — not calibrated probabilities.

Future improvements

  • Optional real AI provider behind the existing AIAnalysisProvider interface.
  • Persistent storage with proper authentication (outside portfolio scope).
  • Visual similarity / perceptual duplicate detection.
  • Export and delivery integrations.
  • Team roles and audit trails.
